## 用途

開発の全体像と、どこまで進んだかを把握したいときに使う。

## 手順

1. 情報を集める
   - `git log --oneline -30` と `git branch` で、完了した作業と並行しているブランチを確認する
   - `git status` で未コミットの変更を確認する
   - `.agents/` 配下(`HANDOFF.md` など)で、進行中の作業と詰まっている点を確認する
   - `docs/` と README で、全体の構成と予定している機能を確認する
   - 会話の中でユーザーが話した目的や予定を拾う
2. 機能・タスク単位にまとめる。commit 単位では並べない
3. 下記の Format で出力する

## Format

```markdown
## 全体像

{何を作っているか、今どの段階か。2〜3 行}

## 進捗

| # | 機能・タスク | 状態 | 根拠 | 次の一手 / 詰まっている点 |
|---|---|---|---|---|
| 1 | {名前} | {状態} | {commit / ブランチ / ファイル} | {内容} |

## リスク・判断が必要なこと

1. {内容。無ければ「なし」}
```

## 状態

| 状態 | 基準 |
|---|---|
| 完了 | main に入っている |
| 進行中 | 未マージのブランチか、未コミットの変更がある |
| 未着手 | docs や会話で予定されているが、手が付いていない |
| ブロック | `.agents/` や会話に、詰まっている点が記録されている |

## Guidelines

- 表は進行中・ブロックを上にし、完了を下にする
- 根拠の列を必ず埋める。根拠が無い行は推測と分かるように「(推測)」を付ける
- 進捗を % で書かない
- 完了した作業が多いときは、直近のものだけ残して「ほか N 件」とまとめる

## Constraints

- ファイルを作成・変更しない
- コミットや push はしない
